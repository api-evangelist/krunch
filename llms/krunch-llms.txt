# Krunch

> Krunch is an on-demand product studio delivering product management, engineering,
> and marketing as a service, using AI and code. Krunch is a services agency, not an
> API provider: it has no public API, developer portal, documentation, SDKs, or
> machine-readable API artifacts.

Generated by the API Evangelist enrichment pipeline on 2026-07-19 from apis.yml and
live probes of www.krunchdata.io. Krunch does not publish its own /llms.txt (probed
2026-07-19, HTTP 404).

## What Krunch does

- On-demand product management, engineering, and marketing services
- Delivery is AI- and code-assisted rather than staff-augmentation-only
- Accepted into the 500 Startup Accelerator program (Silicon Valley)
- Publicly named prior engagements: Alibaba, Google, Camunda, New Relic, Polkadot, Bowtie

## For agents

- There is no Krunch API to call. No base URL, no authentication scheme, no OpenAPI or
  AsyncAPI description exists as of 2026-07-19.
- No first-party Krunch package exists on any registry checked on 2026-07-19. Note the
  name collision: the npm package `krunch` is an unrelated JavaScript build/watch tool
  by larron (github.com/larron/krunch), NOT published by this company. `krunchdata` on
  npm and `krunch` on PyPI both 404.
- No developer subdomain resolves: docs., api., developer., app., and blog.krunchdata.io
  all fail DNS resolution.
- The /.well-known/ surface is empty (see well-known/krunch-well-known.yml): no
  security.txt, no OpenID Connect or OAuth authorization-server metadata, no api-catalog,
  no ai-plugin.json.
- Domain security posture is probed in security/krunch-domain-security.yml: HTTPS with
  TLS 1.3 and HSTS (max-age 63072000) on www.krunchdata.io, but no DNSSEC, no CAA
  records, no SPF, and no DMARC on krunchdata.io.
- Engagement with Krunch is a sales conversation via the Calendly link, not a
  self-service signup.
